# Reproducing the evidence

## Recompute published scores without a GPU

Use the repository's Python standard-library tools:

```sh
python3 -m evals.wildguard.reproduce \
  --evidence published_runs/2026-10-24-wildguard \
  --out /tmp/wildguard-reproduction --intervals
```

Choose a new output directory. The command validates gzip hashes, restores the prompt-free prediction records, checks every summary metric, and recomputes the paired bootstrap and frozen threshold controls. Generated reasons were removed from public Safeguard records; other prediction files must also match their original source hashes after decompression. Raw input/output traces are deliberately not published.

The same command can use the archived source snapshot rather than a future revision of the repository:

```sh
# Start in the repository root, then switch away from its current evals package.
wildguard_evidence="$PWD/published_runs/2026-10-24-wildguard"
(cd /tmp && PYTHONPATH="$wildguard_evidence/source" python3 -m evals.wildguard.reproduce \
  --evidence "$wildguard_evidence" \
  --out /tmp/wildguard-source-reproduction --intervals)
```

The source hashes in freeze.json identify the exact inference and metric implementations. Its `test_opened: false` flag records the state at freeze creation; the test was subsequently opened and evaluated. The freeze and preparation manifests remain immutable historical records. Use a new output directory for each reproduction.

To render the figure, install `matplotlib==3.9.4` in a separate environment and run:

```sh
python -m evals.wildguard.plot \
  --analysis published_runs/2026-10-24-wildguard/analysis.json \
  --out /tmp/wildguard-figures
```

The published PNG was visually checked. The SVG contains editable text; the accompanying CSV contains the plotted data.

## Reconstruct data

Use your own authorized Hugging Face access and the pinned revision in `evals/wildguard/revisions.json`. The upstream dataset's access conditions and ODC-BY attribution apply. Download `train/wildguard_train.parquet`, verify its source SHA256 against training-data-manifest.json, then run the data importer described in the [runner guide](../../evals/wildguard/README.md).

`training-assignments.jsonl.gz` provides IDs, prompt hashes and group/partition assignments without prompt text or full-population source labels. Evaluated-row labels remain in prediction records for metric reproduction. Samples use the deterministic proportional stratification in `data.sample`: pilot 256 fitting rows, search 1,024 fitting rows, validation 512, audit 512. The final fitting file uses `write_jsonl(path, sample(fit_rows, 8192))`. Preserve source-row order and UTF-8 physical-newline JSONL handling. Files can contain Unicode line separators inside valid strings; do not parse with `str.splitlines()`.

The frozen test certificate identifies the original test parquet and derived 1,699-row JSONL hashes. The importer excludes exactly the 26 rows with null prompt-harmfulness labels. Responses are excluded from classifier input. Recomputing the source-based overlap audit requires the gated text and `datasketch==2.0.0`; it does not change the official test population.

This test has already been observed. Reconstructing this experiment is replication, not a new unseen test for policies subsequently developed against its outcomes.

## Rerun model inference

The experiment used one 96 GB RTX PRO 6000 Blackwell Server with NVIDIA driver 580.126.09 and Linux/Python 3.10.12. The runtime folder records complete package freezes and exact versions. Trailing whitespace in the published GPU environment capture is normalized; the original capture remains in the private archive. The native PolicyLM/WildGuard-tokenizer environment uses torch 2.11.0+cu128 and transformers 4.57.6; the serving environment uses vLLM 0.31.0, torch 2.13.0 (CUDA 13.0 build), and transformers 5.17.0.

`source/serve_and_run.py` records the actual model grouping, localhost server flags, checkpoint paths, output caps, concurrency and runner invocations. `source/jobs/` records every phase's explicit jobs. Paths assume a dedicated remote `/root` layout; adapt them deliberately when using a different machine. All model revisions are pinned. Native PolicyLM uses its upstream helper whose source URL/hash is recorded in native-helper.json.

The archived `source/setup.sh` and `source/prefetch.py` are the **historical bootstrap**, not a complete single-command clean-install recipe. The initial setup required later SentencePiece/protobuf installation and a WildGuard tokenizer repair, recorded in the lab notebook. To reproduce the repaired environment, include `sentencepiece==0.2.2` and `protobuf==7.36.2` in both environments, use the recorded package freezes, and run `source/convert_tokenizer.py` under the policy environment before serving WildGuard. Verify vocabulary identity. Input IDs are generated by the original slow tokenizer; the converted fast tokenizer only decodes server output.

Serve pinned local snapshot directories with offline mode after authorized model downloads. Safeguard uses native MXFP4 weights, medium reasoning, the OpenAI reasoning parser, TRITON_ATTN and an 8,192-token cap. Other score models use BF16 and one output token. HTTP concurrency is 32; native PolicyLM is sequential despite the shared CLI concurrency field. Changing hardware, quantization, tokenizer, threshold, policy, or runtime creates a different deployment and must be labeled accordingly.

The four-hour provider cutoff and instance cleanup were operational budget controls, not part of model scoring. The final billing record includes paid setup and inference time. New inference incurs new charges; published-score reproduction does not.

## Archive layout

- `freeze.json`, `selection.json`, `calibration.json`: pre-test decisions and immutable hashes.
- `runs/<run-id>/`: manifest, summary, policy where applicable, and public gzip predictions.
- `run-index.json`, `verification.json`, `reproduction.json`: coverage, hashes and score verification.
- `analysis.json`: paired test comparisons, controls, agreement/category/adversarial slices and overlap sensitivities.
- `repeatability.json`: descriptive search-versus-expanded-fitting consistency check; not a controlled replication.
- `runtime/`, `source/`, `SHA256SUMS`: environments, code/operations snapshots and artifact checksums.
- `private-archive.json`: checksum and size of the separately retained private archive. It contains gated prompts, raw requests/responses and full logs and is not a public download.
- `billing.json`, `final-instance.json`, `ssh-key-removal.json`: provider usage and cleanup evidence.
