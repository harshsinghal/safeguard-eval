# Experiment workflow

The owner has requested that repository updates are part of every experiment,
without a separate reminder. An authorized experiment includes recording its
plan, code, model and data versions, results, limitations, cost and resource
cleanup; linking the readout from the main README; running relevant checks; and
publishing the changes to this repository. Keep experiment headings descriptive,
not date-based. Dates still belong in provenance and immutable run directories.

Register selection rules before examining final results. Preserve failed runs,
amendments and negative results. Distinguish proposed, attempted and completed
work. Never promote a test-selected configuration to a preregistered result.

Do not commit credentials, private infrastructure access details, model weights,
or restricted dataset text. Publish safe manifests, hashes, predictions and
instructions for restoring inputs. Keep existing frozen studies immutable.
Reconcile spending against the remaining authorized budget, use provider-side
termination limits, and verify that experiment resources have stopped billing.

Updating experiment records does not automatically authorize rerunning studies,
increasing spending limits, or rewriting separately reviewed papers, articles or
versioned skill releases. Link new evidence so these artifacts can be revised
deliberately.
